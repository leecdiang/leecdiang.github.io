大模型训练和推理中的通信

两张 GPU 各算一批样本，怎么用梯度更新同一个模型？用同一组梯度对照 DDP 和 FSDP，再看张量并行和 MoE 分别要传什么，以及生成一个 token 要等哪些通信。
LEEcDiangChengzhan Li 2026.11.25 发布

四张 GPU 分别存着 1、5、9、13。做一次 AllGather，每张卡都会拿齐这四个数。

一、四张卡怎么交换数据

如果这四个数是一层权重的四块，每张卡都得拿齐，才能算这一层。如果它们是同一个参数在四批样本上算出的梯度，就要把它们加起来。图中每行是一张卡，r0 到 r3 对应四个通信进程的组内编号（rank）。

图 1｜四种操作的输入和结果。每行对应一张卡，两种归约均按列求和。

切到 AllReduce，点一次「下一步」。第一列的四个数相加得到 28，四张卡都拿到 28。把各卡同一位置的数合成一个结果叫作归约，这个例子用的是加法。[1]

ReduceScatter 也按列求和，区别在于谁拿结果。第一列的和 28 归 0 号卡，第二列的和 32 归 1 号卡，余下两张卡各得 36 和 40。如果此时再做一次 AllGather，四张卡就都有了完整的 [28, 32, 36, 40]。这和一次 AllReduce 求的是同一组和。实际使用浮点数时，加法顺序可能影响结果的末位。[1]

All-to-All 里的列有另一层意思。第一列是各卡准备发给 0 号卡的数，第二列都发给 1 号卡。0 号卡最后收到一整列，四个数原样保留。后面 MoE 要把 token 送往各自的专家，就用到了这种交换。

二、各读一批样本，怎么更新同一个模型

DDP 和 FSDP 各自更新哪些参数

假设模型只有两个待更新的参数。两张卡起初拿着相同的参数，各读一批样本。反向传播结束后，0 号卡算出的平均梯度是 [2, 4]，1 号卡是 [6, 8]。要是各自拿这个梯度更新，两份模型走一步就不同了。

分布式数据并行（DDP）在初始化时可以用 Broadcast，让 0 号卡把同一份参数发给大家。训练时，两张卡用 AllReduce 把梯度逐项相加。如果两批样本含有同样多的有效 token，求和再除以二，两边就能用同一个平均梯度 [4, 6] 更新模型。若损失按 token 求平均，而两批的有效 token 数却不同，就要按各批的有效 token 数加权。[3]

换一种存法。0 号卡平时只保管第一个参数，1 号卡只保管第二个，两份样本照旧各算各的。算到需要这两个参数的层时，每张卡都缺对方手里那一份，于是先用 AllGather 拼齐权重。更新时用 ReduceScatter。0 号卡领到第一项的和 2+6=8，1 号卡领到第二项的和 4+8=12。各自除以二，0 号卡用 4 更新第一个参数，1 号卡用 6 更新第二个。

这就是完全分片数据并行（FSDP）的做法。PyTorch FSDP2 可以把一层或几层的参数编成一组，算到哪组，就收集哪组的权重。梯度和优化器状态也按参数分片。前向算完释放这组完整权重，可以腾出显存，代价是反向算到它时还要再收集一次。[4]

图 2 把两种训练方式放在了一起。DDP 会把多个参数的梯度凑成一桶，按各卡约定的桶顺序发起 AllReduce。靠近输出端的梯度先算出来，所以传第一桶时，GPU 还可以继续计算靠近输入端的梯度。等反向计算结束，最后一桶如果还没传完，优化器就得等它。[3]

八张卡，每步要发多少数据

取一个 80 亿参数的模型，通信时每个参数和每个梯度元素都占 2 字节，权重和梯度各有 16 GB。把权重均分到四张卡，做一次完整的参数收集时，每张已有 4 GB，还要收 12 GB。换成八张卡，每张已有 2 GB，要收 14 GB。

把各卡收到的字节加起来，四卡共收 48 GB，八卡共收 112 GB。若模型大小固定为 S，均分到 p 张卡，每张接收 (p−1)S/p，全组共接收 (p−1)S。若固定的是每张卡带来的分片大小，比如一律 1 GB，那么四卡时每张收 3 GB，八卡时每张就要收 7 GB。[2]

在均匀的八卡环上，每张卡把分片传给下一张，同时从上一张接收，发送量和接收量相等。一遍参数 AllGather 每张卡发 14 GB。等大的梯度做一遍 ReduceScatter，每张也发 14 GB。下表按一步做一次前向、一次反向来算，各参数组采用相同的策略。[2][4]

训练方式 一步里要传什么 单卡每步发送量
DDP 每桶梯度各做一次 AllReduce 28 GB
FSDP2，前向后保留完整权重 收集一次权重，归约并分发一次梯度 28 GB
FSDP2，前向后释放完整权重 前向、反向各收集一次权重，再归约并分发梯度 42 GB

表中只计发送，单位用十进制 GB。FSDP2 多发这 14 GB，就可以在前向结束后释放完整权重。至于每步要多等多久，还要看其中多少通信能和别的层的计算同时进行。

三、模型还能怎么分

张量并行为什么要把输出相加

FSDP 临时凑齐一层的权重，每张卡算自己的样本。张量并行（TP）可以让两张卡同时算同一层里的同一个 token。以 Transformer 里的前馈网络（MLP）为例，输入先经过一次矩阵乘法扩展到较宽的中间层，经过激活函数，再由第二次矩阵乘法投回原来的宽度。

假设中间层只有四个特征。0 号卡算前两个，1 号卡算后两个。要算最终输出的第一个数，第二次矩阵乘法需要把四个特征各乘一个权重，再把四项加起来。0 号卡能算前两项之和，1 号卡能算后两项之和。把两个部分和相加，才得到第一个输出。其余位置也一样。后续算子在两张卡上都要读完整输出，于是用 AllReduce 把两边的结果逐项加起来。[5]

Ur=ϕ(XW1,r)W2,r,Ur∈RT×H,Y=U0+U1.

经典 Megatron 的 attention 输出投影也会产生这样的部分和。一个 Transformer 层里，attention 和 MLP 在前向各做一次 AllReduce。训练反向时，attention 和 MLP 还各有一次输入梯度归约。如果同时启用序列并行，可以把归约后的 token 行分给各卡，用 ReduceScatter 收尾。下一处需要完整序列的列并行算子再做 AllGather。[5][6]

流水线并行只把中间结果交给下一段

流水线并行（PP）把连续的几层交给同一个阶段。假设前 16 层在第一张卡，第 17 层起在第二张。先把一批样本拆成几小份（微批）。第一张卡算完一份，就把第 16 层的输出发给第二张卡，后者接着算第 17 层。边界上的两张卡用一对 Send/Recv 交接这份激活，反向时沿原路送回它的梯度。一个阶段内部仍可以用多张卡做 TP。[7]

MoE 怎么把一个 token 送到它的专家

混合专家模型（MoE）的一层里有多个专家网络。假设 0 号卡上的一个 token 选中了 2 号卡上的专家。0 号卡要把这个 token 的隐藏向量（这一层的输入）送过去，2 号卡算完后再把专家的输出送回。若选中了两个专家，来源卡就按路由器给的权重合并两份输出。

把一批 token 放在一起，各卡先按目的地打包向量，一起发出，这一程叫 dispatch。专家计算完成后，各卡把结果送回来源卡，恢复 token 顺序并合并输出，这一程叫 combine。这就是专家并行（EP）里常见的两次 All-to-All 交换。演示里每张卡给每个目的地各送一格，MoE 的路由器选出来的数量可以不等。通信实现可以为每个目的地指定不同的发送长度。训练反向时，梯度也沿对应的路由交换。[8][15]

四、跟一条推理请求走一遍

读提示词和逐个生成 token，哪一笔通信变小了

一条请求先由调度器交给一个模型副本。如果几张 GPU 各自运行一份完整的稠密模型，它们可以各接各的请求，生成一个 token 用到的层间结果和历史缓存都留在本卡。如果一个副本用了多张卡做 TP，同一条请求每经过一层，就会遇到图 3 的部分和。[5][9]

假设这个 TP 副本有 32 层，隐藏宽度 4096，激活使用 BF16。每个 token 的一行数据占 4096×2 字节，也就是 8 KiB。先读一条 2048 个 token 的提示，整段一次算完，叫作预填充（prefill）。每个 rank 交给一次 AllReduce 的输入就是 2048×8 KiB，合 16 MiB。

生成阶段（decode）里，一条序列每步只算一个新位置。假设这一轮同时推进 16 条序列，一次归约便只有 16 行，合 128 KiB。Attention 仍要读各序列的历史 KV 缓存，但输出投影只为本步新算的 16 个位置产生部分和。两次前向都要经过相同的 32 层，各做 32×2=64 次归约。[5]

图 5｜每次 AllReduce 的单卡输入相差 128 倍，两次前向的层内归约次数都为 64。横轴是输入张量的大小。要换算链路上发送的字节数，还需指定通信算法。

128 KiB 的归约要等多久

用八卡 ring AllReduce 估一次。先用 ReduceScatter 让各卡拿到各自负责的和，再用 AllGather 让每张卡拿到全部结果。每个阶段都绕环传 7 轮。每轮都有启动开销，即使消息很短，这 14 轮也要走完。

代入图 5 的两个数。128 KiB 的输入花在传输上的时间约为 4.6 µs，14 轮启动却要 28 µs。输入增到 16 MiB，启动仍是 28 µs，传输耗时增至约 587 µs。DDP 可以把多个梯度攒成一桶，少付几次启动开销。TP 做 decode 时，下一层要读上一层的结果，每生成一步又要依次走过这些层。实际通信库会按消息大小和拓扑选算法，图 6 算的是选用环形算法时的情形。

如果换一组卡接着生成，历史 KV 怎么办

如果读提示和生成 token 用的是两组设备，接手生成的 GPU 从哪里读历史 KV？提示词的 key 和 value 是前一组 GPU 算的，此时还在它们的显存里。DistServe 这样的系统会在两组设备之间传递各层的 KV 缓存。两边的分片方式如果不同，一张源卡保存的那一片还得拆给几张目的卡。[10]

取一个 32 层的分组查询注意力（GQA）模型，每层有 8 个 KV 头，每个头有 128 个分量。一个提示 token 在每一层都要留下 K 和 V 两份数据。设元素大小为 b，层数为 L，KV 头数为 hKV，头维度为 dh。用 BF16 存储时，有

SKV/token=2LhKVdhb=2×32×8×128×2 B=128 KiB.

这里恰好也是 128 KiB。图 5 的 128 KiB 来自 16 条序列，是一个 rank 在一层里交给一次归约的激活。这里的 128 KiB 属于一个提示 token，把它在 32 层留下的 KV 全部加了起来。提示长到 8192 个 token，整条请求就有 1 GiB 的逻辑缓存。

左右滑动查看完整图表；键盘聚焦后可用方向键。

图 7｜一条请求的提示 KV 全部通过一条等效链路时，发完有效载荷至少需要多久。横轴每单位为 1024 个提示 token，曲线按标出的十进制 Gb/s 计算。

如果这 1 GiB 全要经过一条 400 Gb/s 链路，跑满线速也要 21.47 ms。实际还要算上准备、排队和接收。若分到两条独立链路并行传，完成时间取决于最后传完的那一份。DistServe 因此也考虑设备放置，在跨机带宽紧张时，可以把负责相同层的两段计算放在同一台机器上。[10]

如果 prefill 端先返回首个 token，而 decode 端需要的 KV 还在路上，用户会多等一会儿才看到第二个 token。如果首个 token 由 decode 端返回，这段等待就算在首 token 延迟里。后续的新 KV 由 decode 端就地追加。[10][14]

对照各场景传的数据和等待它的计算
场景 跨卡交换的数据 哪一步需要它
DDP 训练 各卡的梯度，按桶 AllReduce 每张卡用相同的平均梯度更新完整模型
FSDP2 训练 AllGather 收集参数，ReduceScatter 分发归约后的梯度 计算时需要完整参数组，更新时只要本卡的梯度分片
经典 TP AllReduce 合并输出部分和，训练时还要归约输入梯度 同层后续计算读取完整结果
PP Send/Recv 传微批的边界激活，反向传激活梯度 相邻阶段接着算这一个微批
MoE 专家并行 按目的地交换 token 向量，再把专家输出送回 专家先等输入，来源卡再等专家结果
独立稠密推理副本 调度器分发请求，副本间无需交换本次前向的激活 选中的副本独立生成
Prefill/Decode 分离 点对点传递或重新分片的提示 KV 接手生成的设备读取历史缓存

五、到了网卡上，All-to-All 怎么传

回到图 4，从 0 号卡发往 2 号卡的 token，到底走哪条链路？DeepSeek-V3 的技术报告给了一个具体例子。预填充时，发往其他节点的 token 先走 InfiniBand（IB），到了目标节点，再经 NVLink 转交给专家所在的 GPU。专家返回结果时方向相反，先在节点内汇集，再跨 IB 返回。逐 token 生成时，请求对延迟更敏感，这套部署在 dispatch 和 combine 两程都采用 IB 点对点直传，并用 IBGDA 让 GPU 提交通信操作。[11]

流水线里调用 Send/Recv，框架知道要把哪条消息交给哪个 rank。至于网卡怎么交付这条消息，要看传输后端。在可靠连接上使用 RDMA 的 SEND 时，接收方须事先在接收队列挂好缓冲区。若选用普通 RDMA_WRITE，发送方凭远端地址和访问密钥（rkey），直接把数据写入对方授权的内存。启用 GPUDirect RDMA 后，这块内存可以是 GPU 显存。工作请求可以由 CPU 提交，也可以像前面的 IBGDA 配置那样由 GPU 提交。[12][13]

回头看图 5 里的 128 KiB。如果参与这次归约的 GPU 全在同一台机器上，GPU 之间走的又是 NVLink，这次归约产生的跨机网卡流量就是零。要和网卡计数器对账，除了每张卡交给 AllReduce 的字节数，还得知道哪些卡参加了归约、它们之间走哪条链路。
